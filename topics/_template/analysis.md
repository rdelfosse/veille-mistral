## Intention

Une à deux phrases : que cherche-t-on à produire à partir de la veille de ce topic ? (Ex. :
détecter des opportunités de solutions concrètes pour le public cible défini dans `scoring.md`.)
Reprendre le **public cible** de `scoring.md` — il oriente toute l'analyse.

## Acteurs en place (à cartographier)

Liste des acteurs dont il faut cartographier l'offre **existante**, pour isoler ce qu'ils ne
font PAS (les angles morts). Un acteur = un nom + ce qu'il couvre en général. L'agent
angles-morts fera des recherches web sur chacun.

- **Acteur A** — ce qu'il fait globalement (financement, data, outil, plaidoyer…).
- **Acteur B** — …

## Contraintes

Ce qu'une opportunité valable doit respecter / exclure. Ex. : « exclure tout produit purement
financier », « privilégier la souveraineté / les données publiques ouvertes », « déployable sans
compétence technique interne ». Laisser vide s'il n'y en a pas.

## Critères d'une bonne idée

Ce qui distingue une piste exploitable (utilisé par l'agent idées-microservices). Ex. :

1. **Preuve rapide** — produit un résultat démontrable (photo, carte, chiffre) en < N semaines.
2. **Mono-tâche** — résout un seul problème, bien.
3. **Couche laissée vide** par les acteurs en place (exploitation, RH, dernier kilomètre…).
4. **Contrainte respectée** (cf. section précédente).

## Catégories de sortie (optionnel)

Regroupements attendus dans le livrable d'idées. Ex. : « déployables cette semaine », « micro-SaaS »,
« paris d'échelle ». Laisser vide pour une liste simple triée par impact.
